# Orion-Core — команда исследовательских агентов

Эта команда разделяет работу на независимые направления. Профили в `.github/agents/` — это инструкции/роли для совместимых AI coding-agent сред; само наличие файлов **не запускает автономные процессы**. Координацию и фактическое выполнение задач подтверждаем коммитами, тестами и ссылками на источники.

## Роли

| Агент | Ответственность | Основной результат |
|---|---|---|
| **Lead / Integrator** | Архитектура, декомпозиция, интерфейсы между направлениями, интеграция | Согласованные решения, PR/коммиты, отсутствие конфликтов |
| **Platform Researcher** | Официальные различия Xbox GDK, Windows SDK и системных сервисов | Матрица API/сервисов с источниками и уровнем уверенности |
| **Graphics Engineer** | D3D12, Vulkan, GPU queues, memory, descriptors, shaders, presentation | Модель графических возможностей и тестируемые абстракции |
| **Compatibility Engineer** | Windows runtime, файловая система, ввод, аудио, потоки, синхронизация | Каталог несовместимостей и план адаптеров |
| **Format & Asset Analyst** | Форматы данных и пайплайны ресурсов на законно доступных примерах | Спецификации форматов, валидаторы и тестовые fixtures |
| **QA / Evidence Auditor** | Тесты, воспроизводимость, проверка утверждений и безопасности | Автотесты, evidence review, отчёты о пробелах |

## Правила взаимодействия

1. Каждый агент работает в своей области и не переписывает чужие подсистемы без согласования с Lead.
2. Каждое техническое утверждение маркируется как **подтверждённый факт**, **гипотеза** или **неизвестное**.
3. Факты о платформах подкрепляются первичными официальными источниками, датой проверки и точной ссылкой.
4. Неизвестные внутренности GTA VI не выдумываются. Пока нет легально доступных и проверяемых материалов самой игры, исследуем платформенные контракты и строим общие инструменты.
5. Никаких скачиваний/запусков сомнительных утечек, обхода DRM, лицензирования, anti-cheat или иных защит.
6. Никаких изменений пользовательской системы без явного согласия. Диагностика по умолчанию read-only.
7. Каждый результат должен иметь тест, воспроизводимый пример либо объяснение, почему автоматический тест пока невозможен.
8. Lead объединяет результаты только после QA review.

## Очерёдность работы

### Спринт 1 — исследовательская основа
- Platform Researcher: собрать официальную карту платформенных контрактов Xbox GDK ↔ Windows.
- Graphics Engineer: определить графические подсистемы и подготовить словарь возможностей без неподтверждённых выводов.
- Compatibility Engineer: составить перечень OS/runtime-зависимостей, требующих адаптации.
- Format & Asset Analyst: описать безопасную архитектуру плагинов форматов и тестовые данные без proprietary assets.
- QA / Evidence Auditor: определить формат карточки доказательства и критерии приёмки.
- Lead: согласовать общую схему данных и интегрировать первые результаты.

### Спринт 2 — прототипы
- Добавить хранилище evidence/claims.
- Добавить декларативные профили платформ.
- Реализовать сравнение возможностей с явным статусом unknown.
- Добавить тесты схем, сравнения и импорта/экспорта отчётов.

## Definition of Done

Задача завершена, если результат проверяем, документирован, покрыт тестом (где применимо), не содержит выдуманных сведений и не нарушает правила безопасности/правомерного доступа.
